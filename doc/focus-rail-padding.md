# 专注出口、常驻精简栏与列表内部留白

本轮基于 `b90382e5e8c9edaac1267299933ce3266d9e2741`。实现阶段未触发 CI；发布构建须以准确提交对应的运行单独验证。

## 已确认的事件问题

此前 `IDM_FOCUS` 隐藏书签，`UpdateReaderLayout` 在专注时把导航宽度设为零；普通 Esc 没有专注出口，继续进入 `WM_KEYDOWN` 的旧全屏／隐藏窗口处理。全局键盘钩子另有相同分支。Alt／F10 虽能临时显示菜单，却通过 `_navigationAccess` 重新分配正文宽度，缺少鼠标／触摸可发现的常驻出口。

## 最终交互

- 专注始终保留 **48 DIP** 的图标栏，给它分配独立布局区域，正文从栏的右侧开始，不覆盖文字。顶部退出图标始终可见，名称／提示为“退出专注，固定侧栏（Esc）”；原专注按钮在此时也标为退出。
- 静置使用仅栏区域的局部颜色混合，鼠标悬停、键盘焦点、菜单跟踪或栏内鼠标捕获期间恢复清晰配色。高对比度模式保留清晰系统配色。没有边缘唤出、隐藏或轮询计时器。
- 这里是 **混色绘制的半透明观感**，不是真正透过正文的子窗 alpha。没有给主窗口新增透明度设置，不让正文随栏的强调状态变化。用户原有窗口透明度设置仍独立生效；原生栏常驻时继续使用已有的子控件兼容绘制路径，不能把它声称为原逐像素透明文字路径。悬停和失焦只重画栏，不重新分页、移动正文或改阅读锚点。
- Alt／F10、Tab、方向键、Enter／Space 保留。触摸直接点击顶部退出图标即可，不依赖 hover；该图标仍是有名称的原生按钮。
- Esc 优先交给搜索窗口和系统模态界面；在专注会话中先取消分隔条拖动／退出编辑、关闭临时书内面板、结束 Alt／F10 导航焦点，再退出专注。退出后恢复进入前的目录／书签状态及原逻辑宽度。一次长按只处理一个阶段，松键后才能继续，避免退出后旧隐藏窗口命令被自动重复触发。普通模式保留既有行为和自定义键配置；专注会话中的无修饰 Esc 优先保障出口。

## 内部留白

实查目录与书签为 TreeView，书库与正文搜索结果为 report ListView，未发现这四处使用 Win32 LISTBOX（资源中也无独立 LISTBOX 定义）。

目录／书签通过 8 DIP 宽的透明原生图像列增加内部留白，保持已有层级缩进，标签矩形、命中和横向滚动范围继续由 TreeView 计算。DPI 变化时替换共享图像列，替换／销毁时先解除引用，避免重复释放。没有使用官方标为内部用途的 [TreeView_SetBorder](https://learn.microsoft.com/en-us/windows/win32/api/commctrl/nf-commctrl-treeview_setborder)。

书库／搜索按原生行、列和滚动后的列头矩形绘制单元格，在内容内部使用 8 DIP 留白；列头和文字对齐。窄列会缩小留白，保留至少一个像素内容宽度。选中背景仍覆盖整个单元格，键盘焦点框、搜索命中高亮和全行选择保留。其他已有列表不改变绘制策略。没有改动章节、元数据、复制文本或可访问名称，也没有用字符串前导空格制造视觉边距。

## 验证与边界

现有 81 项加新增 8 项，共 **89 项通过**；ASan／UBSan 同样 89 项通过（LSan 关闭，预编译 PDFium 本身不由 sanitizer 重编）。新增测试编译生产 `SetReaderFocusMode`／`ReaderFocusEscape`，验证模态、编辑、拖动、临时面板、菜单、Alt 导航、长按／松键、其他窗口和 200 次重复进入退出。另覆盖 100–200% DPI 的固定栏几何、失焦／鼠标／菜单／捕获强调状态、明暗混色对比、窄列留白及局部重画和原生留白调用约束。

正常／无网络配置各 24 个翻译单元通过 MinGW 语法／API 类型检查。原有正文双缓冲、局部失效、目录同步和 PDF 核心回归仍通过。没有真实 Windows GUI 环境：鼠标／触摸、屏幕阅读器、实际像素留白、全屏／无边框、透明和跨屏 DPI／闪烁仍未实测；不能把数学／替身检查当成这些操作通过。

Windows 复核应包含：纯键盘和触摸进入／退出专注，长按 Esc，搜索／编辑／模态窗口中 Esc，拖动先取消，菜单关闭后栏恢复静置，鼠标跨子控件及失焦恢复，原目录／书签恢复；对文本及 PDF 调整窗口和 DPI、滚动长章名／长路径并复制，确认文本完整、正文锚点不变且强调切换不重画正文。
