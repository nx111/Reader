# 左侧导航、轻量功能与 PDF

## 界面与参考取舍

参考 [Koodo 官方功能](https://github.com/koodo-reader/koodo-reader#features) 及官方亮色书库、暗色书库与阅读截图中的平面层次、单色线条图标、灰色选中和留白。当前版本取消顶部菜单／命令行，以左侧“书库、阅读目录、查找、书签、显示与主题、专注阅读、更多”按钮列表为主入口，底部为返回／前进图标。标题栏和系统菜单保留。

宽窗口通常显示图标与文字；目录／书签打开时主导航收为 48 个逻辑像素的图标轨，和一个可拖动宽度的书内面板共用左侧空间。小于 700 个逻辑像素的窗口使用图标轨和临时抽屉。列表高度不足时自身滚动，头部和返回／前进不随列表滚走。书库嵌入主窗，筛选保留一个下拉框，避免另一个宽导航挤压书籍列表。图标按钮保留原生控件文字作为可访问名称，提供工具提示、焦点框和明暗状态色；图标使用原创 GDI+ 矢量，未复制品牌或 logo。

用户自行改过的快捷键优先于新增导航键，输入框保留编辑键；既有默认导航映射保持。Alt／F10 聚焦“更多”；方向键、Home／End、Enter／Space、Esc 和 Tab 可操作导航，Shift+F10 仍用于上下文菜单，AltGr 不触发菜单。完整旧菜单由“更多”的原生弹出菜单提供，旧快捷键和自定义键配置继续使用。专注时导航隐藏，Alt／F10 可临时显示并在离开后恢复。

正文继续使用独立 `ReaderReadingView` 子窗口及双缓冲，导航、书内面板与正文有不重叠布局。目录跳转、正文滚动和导航历史状态刷新不会重建界面。窄窗抽屉是刻意覆盖，正文仍由父窗剪裁规则隔离。配色集中到既有主题 palette，保留用户自定义正文颜色的语义；PDF 纸张保持原始颜色，不反相扫描图片。系统文件选择器、系统菜单和消息框保留操作系统外观。

## Koodo 功能梳理

| 功能 | Reader 本轮取舍 |
| --- | --- |
| 书库、筛选、收藏、进度、最近阅读 | 已有能力，调整布局、图标和间距，继续索引原文件 |
| 目录、搜索、书签、专注、明暗、字体／行距／边距 | 复用原功能，由左侧入口和“更多”集中访问 |
| 阅读备注和导出 | 新增每条书签可选的 500 字符短备注，以及当前书的 TXT／Markdown 导出 |
| PDF | 新增真实固定页面渲染，包括扫描页 |
| 云同步、账号、AI、OCR、插件、多色划线、复杂笔记系统 | 暂缓，避免依赖、界面和数据模型膨胀 |
| 封面墙、双栏正文、常驻右侧设置 | 暂不机械复刻，保留 Reader 的轻量列表及现有排版 |

书签面板中双击或 Enter 定位，面板保持打开；右键或 Shift+F10 提供备注、删除和导出。“更多 → 阅读 → 添加书签”提供可发现的创建入口，“导出本书书签”也可导出空书签列表。备注留空或取消均可，重复保存不会改变阅读锚点。导出只在用户主动选择的路径写入 UTF-8 TXT／Markdown；先写同目录临时文件并刷新，再原子替换，失败保留原目标，不联网或上传。

## PDF 能力及边界

- `.pdf` 进入统一的打开、拖放、命令行、书库添加／递归导入和重新关联流程，扩展名不区分大小写。元数据可用时记录标题、作者和页数，失败回退文件名。
- PDFium 显示固定页面、图片与扫描件。PageUp／PageDown 翻页；滚轮在长页内滚动，到边缘可翻页；水平滚轮／Shift+滚轮平移。滚动条反映当前页视口。“更多 → 阅读 → PDF 页面”提供适宽、整页、放大和缩小；已有可配置字号缩放快捷键在 PDF 中改变页面缩放，文本字号配置保留。
- 续读持久化页号、缩放与归一化横纵偏移，调整窗口／DPI／面板仍保留页内锚点。永久书签按页保存，返回／前进另外保存本次会话中的页号和页内位置。PDF 不进入文本编辑模式。
- 展示 PDF 的内嵌本地目录目的地；无目录时面板为空，不伪造章节。查找明确限定“PDF 当前页文本”，结果定位并框选命中文字；扫描图片无 OCR。每页最多提取 250000 个 PDF 字符，不宣称整本文字搜索。
- 页面在工作线程按需呈现，旧代次可协作取消，迟到结果按书籍请求编号丢弃。最多保留两帧、合计约 64 MiB 的像素／文字缓存；单视口最多 8 Mi 像素，超限明确显示呈现失败，不预渲染整本。PDFium 自身解析和解码内存不等同于此应用缓存上限。切书退出会等待已取消工作结束，不强制终止 PDFium 线程。
- 密码保护文件当前明确报错，不提供密码输入；损坏／非 PDF、缺组件、组件位数或系统不兼容均明确报错。自定义文件流长度为 32 位，达到 4 GiB 的 PDF 不支持。
- PDF 使用普通独立正文子窗口；全屏／无边框可用既有整体透明度，PDF 不走逐像素透明文字合成路径。其他格式保留原路径。纸张原色和文档字体不受 Reader 的文本颜色／字号替换。

## 依赖来源与构建

使用获用户授权的 [bblanchon/PDFium chromium/8125](https://github.com/bblanchon/pdfium-binaries/releases/tag/chromium/8125)，固定生产仓库提交 `4bdb7acd45b39ef6a7fc2a5b4c83f0398e45c9a6`。这是第三方预编译包；PDFium 官方源码在 [pdfium.googlesource.com](https://pdfium.googlesource.com/pdfium/)。包内 `args.gn` 确认 `pdf_enable_v8=false`、`pdf_enable_xfa=false`；应用不加载表单、脚本或外部操作 API。

| 组件 | 压缩包实测 | DLL 实测 |
| --- | ---: | ---: |
| x64 | 3,904,987 bytes | 7,586,816 bytes |
| x86 | 3,763,547 bytes | 7,011,328 bytes |

完整 SHA-256、DLL SHA-256、签名工作流与本地验证记录见 [dependency.json](../opensrc/pdfium/dependency.json)。三个测试／分发架构的下载包均通过 GitHub CLI 2.103.3 验证，检查签名证书、工作流、固定源提交、GitHub hosted runner 以及 Rekor 日志证明，日志时间为 2026-10-26 15:18:42 UTC。根信任从 Sigstore 官方仓库取得并留存为单行 JSON，便于脱机重验；不是把同一发布包内的自签声明直接视为可信。

完整保留归档的 `LICENSE`、18 份 `licenses/*`、FTL 致谢及 notices；没有引入 MuPDF／AGPL 引擎。Reader 原作者条款保持独立。公开头文件保存在 `opensrc/pdfium/include`，DLL 放 `.deps/pdfium/x64`／`x86` 并由构建复制到 EXE 同目录；不安装到系统、不改 PATH，不在阅读时联网获取组件。现有系统 PDF API 需要包身份的兼容问题没有通过引入 MSIX 改变便携模式。

在已安装当前 GitHub CLI 和 MSBuild 的 Windows 上先执行 `pwsh scripts/fetch-pdfium.ps1 -Architecture x64`（32 位用 `x86`），再按项目原参数构建。脚本核对 release、哈希及 attestation，失败即停止。workflow 的本地修改增加依赖验证和 x64／Win32 矩阵，包中携带 DLL 与完整 notices；触发条件、权限、secrets 和上传参数不扩大。实现阶段未主动触发 workflow；发布后查询准确提交对应的运行，构建结果单独报告。

两个 DLL 的 PE 导入已检查，无外部 VC 运行时 DLL；PE 标记的系统／子系统版本为 10.0，本轮预编译 PDF 组件以 Windows 10／11 为目标，不承诺 Windows 7／8／XP 上的 PDF 兼容性。没有修改现有其他格式的分派或要求系统安装，组件加载失败保留其他格式阅读能力；所有 Windows 版本的实际运行仍待实机验证。

## 缓存及验证

缓存升为 v5，新增可选书签备注和 PDF 视图字段；v1–v4 的稳定身份、顺序、进度、书签、主题与宽度保留，迁移前留 `.cache.dat.v4.bak`（其他源版本使用各自版本号）。非法备注／偏移／缩放值拒绝覆盖；合并重复位置时保留备注，合并后超过备注容量则安全失败，原记录不变。

最终可移植回归为 81 项：原有 57 项按最终左侧布局修订，新增 15 项导航／图标／布局／导出／PDF 语义回归、8 项真实 PDFium 核心测试和 1 项备注／PDF 状态迁移。实际 PDFium Linux 共享库已核验并执行，覆盖文本页／扫描页像素、目录、文本坐标、损坏与密码、缺依赖、取消、分配上限、重复打开关闭和并发；这是生产核心的真实调用，不是 PDFium mock。ASan／UBSan 亦通过 81 项，预编译 PDFium 自身未以 sanitizer 重编；LSan 禁用。

MinGW 类型／语法检查覆盖 24 个翻译单元的网络与无网络配置；资源经无损 UTF-16 临时转换和 SDK 大小写别名后编译。它们不等于 MSVC 链接或 Windows GUI。当前环境无 MSVC／Windows 桌面／PowerShell，真实菜单焦点、屏幕阅读器、Windows PDF 像素、100–200% 实际 DPI、全屏／无边框／透明和闪烁均未实测，最终新 EXE／7z 包体增量也尚未实测；上表为实际依赖大小，不能替代最终包数字。

Windows 终验应在 300×500 和宽窗中反复开合面板、Alt／F10／Tab／Shift+F10、拖动分隔条、导入取消、备注保存／取消与覆盖导出；分别检查文本书与文本／扫描 PDF 的快速换书／翻页／缩放／续读／书签／搜索定位，跨 100–200% DPI 和四种窗口模式保持锚点，确认正文变化不擦除导航。
